给公司内网知识库做个全文检索后台。员工在内部 wiki 上写的技术文档、接口说明、会议纪要都要能搜出来，搜索要快、结果要准。前端用 React，后端用 Rust（公司想试一下 Rust 在服务端能跑成什么样）。数据全在内存里存一份原始文本加倒排索引，重启重新构建即可。

后端用 actix-web 起 HTTP 服务，路由分组：`/api/docs` 文档管理（GET/POST/PUT/DELETE）、`/api/search` 搜索（带 q/type/limit/offset 参数）、`/api/autocomplete` 自动补全、`/api/force-rebuild` 手动重建索引。倒排索引用 `HashMap<String, Vec<(DocId, position, tf)>>` 存词到 posting list 的映射，加 RwLock 保护。BM25 用经典公式 `IDF * (tf * (k1+1) / (tf + k1 * (1 - b + b * dl/avgdl)))`，k1=1.5、b=0.75。Rust 端用 rayon 并行算分数，搜索 P99 要在 50ms 以内。

文档源在 `docs/` 目录下，启动时递归读所有 `.md` 文件加载到内存，每篇文档有 id、标题、作者、tags 数组、创建时间、正文。倒排索引按词切分，中文按字符 bigram 切（不引入分词库），英文按空格切，索引存词到文档 id 列表的映射。要支持中英文混排，搜索时把 query 也按同样规则切词，然后求并集或交集。query 解析简单实现：用 split_whitespace 切，中文段走 bigram。

搜索接口要支持：单关键词搜索（默认 AND 语义）、多关键词空格分隔（也是 AND）、短语搜索（用双引号包起来的整体算一个词）、按 tag 过滤（`tag:rust` 这种前缀语法）、按作者过滤（`author:zhangsan`）、按时间范围（`after:2026-01-01` 这种）。这些语法可以混在一段 query 里，比如 `rust 内存管理 author:张三 after:2026-03-01`。query 解析按 token 化处理：引号短语是一个 token，prefix:xxx 解析为 filter。

返回结果要带相关度评分、命中关键词高亮（前后各 30 个字符的片段）。高亮从原文中找命中词位置，取前 30 + 词长 + 后 30，返回的字段叫 `snippet`。

搜索结果要能分页，每页 20 条，按相关度倒序，相关度计算简单用 BM25 即可（不用上深度学习模型）。还要有一个自动补全接口，输入前缀返回 10 个最热门的搜索词，热度按历史搜索次数累加。搜索历史本身也要存，记录 query、搜索时间、用户 ip（如果有的话），但只是存着不做分析。自动补全按 prefix 在历史 query 表里查，热度按 count 排序。

文档要能增删改查，但都是基于内存里的数据。增加文档时同时更新倒排索引；删除时把对应倒排列表里的 id 摘掉；修改相当于删了旧的加新的。批量导入要支持一次传 1000 篇文档不卡死。批量接口走 chunk 拆包，每 100 篇一次写索引，用 rayon 并行。批量接口要返回成功数、失败数、失败原因列表。

前端要能预览 Markdown 渲染效果（前端自己渲染就行，搜出来的文档字段就带 markdown 原文）。

搜索高亮在 React 端用 dangerouslySetInnerHTML 把命中词包一层 span 就行，但要注意 XSS——文档里可能有用户写的 `<script>` 标签，渲染之前要么后端转义要么前端用 DOMPurify 处理一下。后端要先把 markdown 转 HTML 再 escape 一遍，存到 doc.html 字段，前端用 DOMPurify 二次清理。

输入校验要细：query 最大长度 200 字符、tag 数组里不能有重复、文档标题不能超过 100 字、正文不能超过 1MB。单文档导入和批量导入都要校验。空 query 返回 400，词切完是空数组（比如全是标点）也返回空结果不要报错。Rust 端用 serde 做反序列化校验，错误返回 400 + 错误字段名。

前端要有一个搜索历史下拉框，点过哪个直接补到搜索框里。还要支持搜索结果导出 JSON。后台要有一个接口强制重建索引（万一内存里数据乱了）。

再补：搜索结果页要展示总命中数和搜索耗时（毫秒级）。自动补全接口要支持模糊匹配（不仅是 prefix，还包含子串）。搜索历史要能删除单条或清空全部。文档管理接口要支持按 tags 多选过滤（AND 语义，所有 tag 都包含才返回）。

还要：搜索结果页要展示"分词结果"（把 query 切成什么样显示给用户看），方便调试。文档管理接口要支持按作者筛选。前端搜索框要支持"回车搜索"和"实时搜索"两种模式（防抖 300ms）。
